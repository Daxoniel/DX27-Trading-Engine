# 多日研究账本、统计与来源守卫：工程验收

本次只实现离线工程路径，使用构造数据验收，不采集新行情，不运行A/B历史评价。
[固定设计](evaluation-design.json)的字节保持不变；其中源码快照和“未实现”清单是
PR55时的历史状态，不能当成当前动态就绪状态。本文件记录实现进展。
执行登记仍未生成或公开，自动paper／实盘始终OFF。

## 模块与资金

- `research.opening_direction`：单日规则支持显式`starting_cash`，默认资本与原规则不变。
  该值控制当日风险、名义仓位和现金预算；入参必须为正有限数。
  输入时间规范化为UTC，避免同一瞬间的不同UTC偏移导致恢复后的字符串事件不同。
- `research.multisession.OpeningDirectionSequence`：调用方提供固定、有序、无重复的评价日历，
  每个计划分钟恰好提交一次。每个profile前一日结束现金成为下一日资本，不每日重置。
  零交易日也保留并传递资本；一个profile缺数据／未平仓／资本非正时停止其后续日，
  其他profile仍保留诊断，整个比较不得输出可采纳绩效。
- 不修改原30分钟引擎、默认风控、RVOL或Sentinel。R0/R1日内逻辑不增加指标或选参。
  本次显式执行R1提前10分钟停止入场的边界，包括构造的很短交易时段。

输入和输出前缀保留在内存，不声称总内存恒定。多日checkpoint包括完整日历和各日输入前缀；
重建时从起始资本重新计算，校验逐日资本，不能通过改checkpoint中的次日金额补资。
重复分钟、错序日历、跳过未结束日或在阻断后继续都拒绝。
单日checkpoint升级为`opening-direction-fixtures-v2`，含起始资本；旧v1不静默升级。
调用方负责原子存储；没有生产订单持久化、锁、借券或broker对账能力。

## 固定统计与账本复核

`research.statistics`独立复算日资金链、成交现金流、每标的净库存、平仓损益、
参考价毛损益减佣金／点差／滑点、逐分钟现金+持仓=权益以及日终与分钟权益一致性。
必须覆盖整个评价日历及每个分钟；任何profile缺失或有质量问题，都阻断比较，不能删日。
报告毛净分解、回撤、交易数、零收益日／零交易日和分钟结束快照持仓暴露比例。
未登记的序列始终performance_admissible=false，engineering_complete只表示工程完成；
正式守卫通过且三组完整后，外层才给出有条件的历史评价可采纳标记，不是下单许可。

按设计输出R1扣模型成本收益和与原三ETF基准的成对差值；R0只作解释性参照。
循环配对区块bootstrap固定5日及20日，10,000次、PCG64种子20261015、线性95%区间；
分别复合再计算差值，保留零交易日，不按交易独立抽样，不挑有利块长。
额外0／1／2／5bps成本场景使用固定成交股数与参考换手；盈亏平衡成本可为负，
零换手则未定义。不是重新调整仓位后的压力回测，也不是实际券商收费校准。

统计函数自身只产生`COMPLETE_OFFLINE_ARITHMETIC`，不授予研究登记或交易许可。
有界重采样分配上限用于拒绝异常大请求，不改变固定设计的正常设置。

## 合成入口与正式入口

`research.evaluation.evaluate_synthetic`只接受显式`SYNTHETIC_DEMO`输入，
同时调用R0/R1序列和原30分钟引擎。原基准预热不交易，预热权益从评价统计排除；
仍核对基准完整上下文日历，不能借裁剪掩盖暖启动交易。
不完整运行返回阻断报告、主要收益为空，并保留各profile诊断账本。

`run_registered`在打开quote CSV之前调用登记守卫。它不下载、不注册、不自动发布，
也没有自动调用它的CLI或后台任务。只有单独完成并公开执行登记后才能使用该路径。
实际CSV由原`load_csv`核对CSV和响应档案的字节hash，随后才检查完整计划日历。

## 执行登记必须另行完成

将来的独立登记文件必须包含：

- `contract=ORB_FIXED_EVALUATION:1`、`status=REGISTERED_OFFLINE_RESEARCH`、指定A或B；
  `evaluation_registered=true`，但`execution_enabled=false`永远表示broker未启用。
- 固定设计SHA-256、当前整个`src/dx27` Python文件集合和字节hash，
  Python major.minor与numpy／pandas／exchange-calendars版本，以及A/B完整日历身份。
  这是约定的源码／依赖守卫，不声称锁定全部OS、硬件和外部运行环境。
- `registered_at`和重新审计记录：审计文件真实字节hash、生成／检查时间、
  针对对应阶段的`NO_ADDITIONAL_EXPOSURE_RECORDED`结论。旧PR55快照不能直接充当新检查。
- 独立公开回执：登记文件hash、40位公开提交ID及发布时间。回执不能放回登记文件形成
  自引用；应由工作流程在公开提交之后另行取得和核实。

**公开回执的真实性由工作流程独立核实。离线代码不联网认证GitHub，
也不能仅凭JSON声明证明已经公开或证明无人查看过数据。**
它只检查证据的结构、指纹、一致性和时间顺序；这是可复核的研究流程，不是认证或权限系统。

数据必须为声明SIP/raw、三标的、精确请求窗口，bar为有时区的一分钟起始标签；
无重复、所有常规分钟正成交量，元数据行数一致，采集开始严格晚于公开登记且完成时间不在未来。
不得以IEX替代；原始接收截点和修订历史仍未验证。

B还必须提供已公开A报告的文件与hash、公开提交／时间，确认A完整、同设计／源码／依赖，
并且A分析完成早于其报告公开、公开早于B采集。**没有A盈利门槛**；负收益不能成为省略B的理由。

## 本地报告写入

`write_local_artifacts`只创建新目录，拒绝覆盖；输出三组summary／daily／fills／trades／
equity／decisions／quality以及总体report。`completion.json`最后写出并列出各文件hash，
包含study_status；“文件完整”与“研究完整”是不同字段。
不完整研究也可保存诊断；主要收益仍为空、状态仍阻断。写入异常保留没有完成标记的目录，
不自动删除、重试或伪造完成。文件尽量使用本地私有权限；不声称跨平台整目录原子事务或fsync保证。
报告保留本地，不自动上传原始行情或逐笔数据。
