## 身份检查的边界与依据

官方[单个资产接口](https://docs.alpaca.markets/us/reference/get-v2-assets-symbol_or_asset_id)支持按代码或 asset ID 查询当前资产；它本身不提供与旧归档的经济身份连续性证明。官方[公司行动说明](https://docs.alpaca.markets/us/reference/corporateactions-1)指出数据可能延迟，而且默认 complete 会过滤部分不完整事件。因此本次请求 `data_quality=all`、全部类型并取完分页。空响应也不能证明没有事件。

准入要求所有原基础同行池参与者、四组目标及八本账户已有持仓都覆盖身份审查，而非只审查赢家或最终十只股票。每份审查文件绑定当前资产 ID、原归档池摘要、公司行动响应摘要、审查时间、经济连续性解释、行动会计解释及带 URL 的原始来源文件哈希。未解决改名、股权注销／重组、并购或未定价权益时，不能用代码相同、名称相似或空事件列表替代审查。RV1a 的八个隔离代码及其有限区间证明不会自动沿用。

这些字段与摘要保证证据一致性、覆盖和可追溯性，**不能自动证明审查内容真实**。审查者仍须逐项阅读适当的发行人、交易所或监管来源。基于复权收盘价的影子账本也不能代替券商公司行动会计。

## 从输入到准入的检查

手动入口使用实际当前 UTC 时间，不提供倒填运行时间的参数。首次形成期收盘前返回 BLOCKED，执行日开盘时及之后返回 SKIP_CYCLE_INCOMPLETE；不能顺延成交。对应首次时间仍为 2026-10-30 20:00 UTC 与 2026-11-03 14:30 UTC。[本次实际决定收据](decision.json)为形成期尚未收盘。

在有效窗口内，检查器会：

1. 核对原 4,002 股票归档池及全部响应字节、请求参数、开始／收到时刻；所有形成期输入均须在形成期收盘后获取，并早于执行开盘。
2. 要求覆盖全池加 SPY 的 raw 和 all 日线请求，使用同一完整回看窗口，不拼接新旧复权版本；核对分页、日期、值和 SPY 交易日历。没有行情的股票可以按原历史完整性规则落选，不能把未查询过的股票静默移出归档池。
3. 动态核对前 36 个月因子；重新计算原资格与独立回归／排名，并与封存排名及输入摘要比对，不能信任调用方给出的“审计通过”布尔值。
4. 核验四个选择器各两档成本的 **八本真实日志目录**、注册日历、初始资金、成本档、哈希链及独立会计审计。已有持仓从这些日志重放得到，不能由调用方填写一个空持仓列表绕过。
5. 核对公司行动页、当前资产与身份审查覆盖。行动查询从归档日起至实际接收当天，决定与查询须同一 UTC 日；并不承诺该日稍后不会有新公告，也不预言尚未公布的行动。

满足时只输出 SHADOW_INPUTS_ADMISSIBLE，仍明确 `execution_enabled=false`，不记模拟成交、不下单。此入口尚未接成每日采集—准入—账本更新的自动运行服务。后续每次实际模拟记账仍须有当日输入与持仓／公司行动准入；没有安装调度器或开始前向业绩。

当前成功的集成夹具为全现金场景，用于覆盖原始快照到重算排名再到准入的通路，不能称真实非空持仓已完成端到端验证。非空排名与账本的旧数据证据仍是 RS1 演练。时间戳依赖受信任本机时钟；没有外部时间公证或数据源真实性证明，不能把收到时间改称原始发布日期。
