本轮只对已经看过的 A/B 记录进行分组与账目重建，**没有重跑策略、获取新行情或验证新候选**。按[协议](../../../research/orb-diagnostics/protocol.md)报告全部固定项目，不合并 A/B，不选方向赢家。文献与实现的差异见[核查记录](../../research/orb-literature/review-2026-10-16.md)。

协议与脚本在 PR #62 的提交 `1ea44d2` 公开后才执行汇总，远端字节已核对，见[发布记录](protocol-publication.json)。由于 A/B 原报告和部分示例记录早已查看，这只建立诊断过程的时间记录，不构成结果盲态或事前收益登记。

这是理想化低成本 R0 实际共享账户路径上的方向贡献，两行加总对应各期 R0 原净损益。它们不是删除另一方向后重新计算仓位的独立策略收益，不能拿其中一行当新回测。R0 没有模拟借券可用性、借券费与真实保证金；此结果不授权开空头。

结果支持把“从多空变为只做多”列为下一阶段待诊断因素，但不能量化该修改对 R1 的单独损害：R1 同时改变时间、风险、名义仓位、量限制、退出与成本。A 的 R0 多头贡献本身为负，也再次说明不能把所有亏损都解释为费用。

没有单笔交易从毛盈利被费用直接翻成净亏损，但每笔收益被削弱、每笔损失被扩大，足以使 B 的总毛利变成总净亏。零个“翻负交易”不意味着费用不重要。成本是既定模型算术，并未用实际报价或适用账户总费表校准；不能靠改低成本假设宣布盈利。该分解没有重新调整股数或路径。

A 覆盖 251 日、B 覆盖 64 日。R0 仅 B 有 1 个 doji 不交易日。R1 的 A 零交易日为 136：129 天 `SHORT_DISABLED`，另 7 天先产生 LONG 信号，入场参考价到首五分钟低点距离非正，记录 `NONPOSITIVE_R`。B 的 34 个零交易日分别为 32 天拒绝空头、1 天非正 R、1 天 doji。

R1 同一日的 LONG 和 NONPOSITIVE_R 是两个事件，不是两个交易日；完整事件计数亦保留。无 ZERO_QUANTITY 事件，只能说明本次没有因最终股数为零而放弃入场，不能说明风险/名义/量限制没有约束实际股数。

这 7+1 个非正 R 日证明定时入场后存在交易集合差异；不能从这些计数推出一分钟延迟总共赚或亏多少。它也不是实现故障的证据：该拒绝规则已在 A/B 之前固定。

## 5. 验证与可复算入口

[脚本](../../../research/orb-diagnostics/fixed_artifacts.py)仅用 Python 标准库。对每阶段本地 report/completion 与公开文件逐字核对、固定报告哈希、22 个实际产物哈希全部通过。使用 Decimal 重建每笔的参考价毛损益、现金流净损益、佣金及摩擦，再核对原 trades、每日资金链、summary 和原公开报告，绝对容差 $0.000001。核对全部计划日和零交易日，没有丢弃损失记录。输出 JSON 的 Decimal 值在通过审计后转换为常规数值，不宣称浮点序列化保留任意精度。

在保有原本地封存产物的仓库运行：

```sh
python -m unittest discover -s research/orb-diagnostics -p 'test_*.py' -v
python research/orb-diagnostics/fixed_artifacts.py --root . --output work/orb-diagnostics/new-attempt.json
```

输出路径必须尚不存在。没有本地产物时拒绝运行，不自动下载行情。CI 只测试构造数据的会计及错误拒绝，不上传或依赖私有原始记录。8 项构造测试本地通过；Ubuntu/Windows 最终提交检查以 PR #62 的实际状态为准。[报告](report.json)与[验证封印](validation.json)保留输入和脚本指纹。

## 6. 研究决定

当前记录把两个问题具体化了：R1 删除的空头在 R0 中有正贡献；一分钟延迟后的价格条件使少数多头信号不再可交易。同时，R1 的毛优势弱、模型摩擦显著，不能只靠恢复一个分支就承诺盈利。

下一阶段需要在另行公开的探索协议中固定逐因素重放的定义和全部分支，才能分别研究方向、延迟、提前平仓及仓位/费用的影响。尤其“让 R1 做空”涉及账户与借券条件，不能仅切换一个布尔值后称为可交易版本。因素交互及资本路径也必须说明。本轮没有选出新候选，没有新样本效果确认，策略与下单状态维持不变。
