# Paper意图归属与累计回报对账：工程验收

2026-10-19。研究继续以Paper为基础，不以实盘费用校准阻断。本轮完成[持久化登记与观测模块](../../../research/orb-diagnostics/paper_intents.py)及构造验收；没有订单提交接口。生产src、旧R1及A/B研究封印不变。

## 已实现

- 固定命名空间`orb-paper-r1-v1`，从稳定intent_id生成不超过48字符的client ID；同一意图重试/进程恢复保持ID。载荷变更或同signal_key换ID会记录完整性暂停，避免悄悄另建意图。
- 写入本地SQLite后才视为已登记；观察到的broker创建时点不得早于该持久化时点。只按精确client ID、方向/标的/数量和broker ID绑定归属，前缀不能证明归属，未知订单不进策略账本，也不能事后补登记认领。
- 复用原`LifecycleJournal`的单写者锁、FULL同步和审计链；没有降低落盘保障。hash链能发现局部损坏，不认证输入生产者，也不保证提交恰好一次——本模块根本不提交订单。
- 复用原`OrderReport`与纳秒版本时间规范，按累计数量/成交额/费用更新；重复事件、同版本等价回报和旧回报不重复累计。相同事件/版本内容冲突、累计数据倒退或成交重新定价则暂停新增意图。
- 部分成交、取消后的权威晚到成交、买卖现金流和库存贡献均有验收。未知费用可继续记录生命周期，但含完整费用现金差保持null；不能把未知变为已验证0。同一订单版本的费用证据变化仍会报冲突，不能人为加版本掩盖；真实独立迟到费用源的接入尚未实现。
- SYNTHETIC与PAPER_OBSERVATION持久化模式隔离；历史重放不能注册成当前Paper信号。真实模式使用本机记录时钟，不允许注入构造时钟；未解决的跨时钟误差会拒绝相关回报，不自动改写时间。

登记中的feed、输入hash、signal/ready时间是显式声明，不证明实时来源、完整首五分钟或时钟同步。尚无市场信号到意图的自动适配器、Paper下单器或完整账户快照对账。完整性暂停后仍可记录既有订单观测，但不创建新意图。SQLite状态和事件记录会随研究增长，不声称常量内存或无限期运行能力。

## 验收结果与边界

本地55项测试通过（原37项，加18项新登记/对账案例），包括恢复、重复、部分成交、晚到成交、未知费用、归属冲突、单写者、日志损坏和构造/实际模式隔离。专用Ubuntu/Windows CI运行同一构造套件，只需源目录导入，不取账户或行情。

[构造示例](synthetic-example.json)使用独立SYNTHETIC数据库：买入累计4股后再累计至10股，重复回报不多记；卖出10股，已声明费用两边各$0.25，最终资金贡献$9.50、库存贡献0。重开数据库后重复报告仍不增加资金贡献。该$9.50是构造现金流，不是实际Paper交易收益；即使构造闭环结束，`actual_strategy_paper_pnl`仍为null、完整账户对账仍为false。

首轮Windows检查发现损坏日志测试的辅助SQLite连接未显式关闭，临时目录清理失败；已用明确关闭的上下文修正测试，未改记录逻辑或降低日志持久化。

真实模式登记库已在本地初始化，但[匿名状态](paper-registry-summary.json)显示登记意图/已归属订单均0。没有伪造当前市场信号或为了生成绩效强行交易。数据库、client ID与原HTTP响应留本地；默认私有文件权限尽力设为0600，跨平台权限语义取决于系统。

这是有界抽样，仍标明历史不完整、非原子快照、未核实策略归属。空样本不能证明费用0、完整历史0成交或策略收益0。没有查询真实账户主机、读取凭据内容、重置账户、创建或取消订单。所有公开输出不含账户标识和私有订单内容。
