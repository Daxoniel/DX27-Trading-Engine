# 探员：P0–P3 研发路线

2026-10-14 修订。探员是 `tanyuan_orb` 日内机器人，与进入维护状态的 Sentinel
市场报告分别管理。本路线以真实数据、共享决策逻辑和可恢复执行为交付顺序。

## P0 — Alpaca 账户连通性

已完成历史 SIP 下载与 INTRA-1A 回放的真实验收。提供只读 paper account、clock、
positions 诊断，报告不保存 key、account ID、account number 或远端错误正文。
GET 使用固定 paper 域名，拒绝重定向，不具备下单入口。

当前云环境三个账户请求均为 HTTP 401：只有行情访问成功，账户验收未完成。
环境 key 绑定仅覆盖行情域名，需检查预期 paper 账户的凭据及账户域名绑定。
401 本身不能区分域名注入、账户凭据或权限问题。账户状态、交易禁用标志和持仓
数量需由真实响应确认；只读连通成功也不代表订单/实时 SIP 权限通过。

## P1 — 实时行情与 Shadow Mode

下一交付：接收分钟行情，使用与回放一致的 30 分钟 ORB、ADX/ATR、风险门限与
可选开盘 RVOL，只保存假想信号、拒绝原因和假想订单，不调用交易接口。
保留 stream feed、接收时间、分钟结束/修订时间、日历版本和配置摘要。

验收需要真实订阅权限、重复/乱序/迟到/修订处理、交易日与提前收盘、跨日重置、
历史预热、断线补齐和重启去重证据。历史数据的假设可用时间不能冒充实时接收证据。
行情 feed 必须显式记录；SIP 开盘均量不得与 IEX 分子混用。

## P2 — 自动模拟交易

默认自动下单开关关闭，仅 paper endpoint；真实账户不在此阶段范围内。
在启用前完成持久化 intent/client_order_id、回报去重、部分成交、拒单/撤单、
网络故障、进程重启和账户/持仓对账。状态不明时暂停新开仓，不能盲目重发订单。
Shadow/回放共享决策代码，但真实成交数量/价格/费用以 broker 回报为准。

## P3 — 策略效果评估

INTRA-1B 开盘相对成交量筛选是历史研究准备，默认关闭，不修改 INTRA-1A 基线。
首个工程配置固定为前 20 个计划交易日同一 09:30–10:00 区间均量，阈值 RVOL >= 1.0。
该数值未拟合、未复刻文献的五分钟策略，也未建立盈利证据。

INTRA-1C 预先声明数据时期、股票池、成本和比较规则；比较同一数据/成本的固定
基线与筛选版本，并保留未触碰的评估期。真实 Q1 数据已经用于本次验收，因此
不能再称作未触碰的独立验证期。随后比较历史、shadow 和 paper 的信号一致性、
收益、回撤、滑点、成交差异及数据质量。通过软件验收不等于策略效果通过。
